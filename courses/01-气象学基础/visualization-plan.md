# 01 气象学基础：教学图与学术图

## 先区分两类图

OpenAtmos 需要两种不同的图，不能用同一套标准处理：

| 类型 | 首要任务 | 典型形式 | 必须回答的问题 |
| --- | --- | --- | --- |
| 教学图 | 帮助初学者看见概念关系 | 关系图、剖面图、流程图、带标注的示意图 | 读者看完后多理解了哪一个关系？ |
| 学术图 | 准确、可复现地呈现数据证据 | 时间序列、剖面、散点图、分布图、地图 | 数据从哪里来，处理后支持什么结论？ |

教学图可以适度抽象，但不能制造错误的因果关系；学术图可以复杂，但不能依赖作者口头解释才能读懂。

## 当前作图 skill 的判断

项目本地已经有 `teach`、`prototype` 等可支持教学内容设计的 skill，但没有发现专门的 `academic-figure`、`matplotlib-figure` 或“论文作图” skill。系统 `visualize` 的定位是创建交互式可视化和探索工具，适合回答“怎样让学习者调参数观察变化”，不负责自动保证论文图的资料溯源、统计标注和发表规范。

因此本轮采用分层方案：

1. 概念关系图优先用 Markdown + SVG，方便 GitHub 阅读、版本控制和无障碍替代文字；
2. 真实数据图优先用 Python 脚本生成，候选工具链为 Matplotlib、xarray、Cartopy 和 MetPy；
3. 交互探索另行使用 `visualize` 或网页组件，不把交互效果当作论文图；
4. 当第一张真实气象数据图完成后，再把实际经验固化成项目级 `academic-figure` skill。

## 学术图的最低可复现要求

每一张数据图至少保存以下信息：

- 数据集名称、版本或访问日期、原始链接；
- 变量名、单位、时间范围、空间范围和缺测处理；
- 计算或重采样方法，以及必要的参数；
- 生成图表的脚本和依赖环境；
- 图题、图注、坐标含义、色标含义和不确定性说明；
- 优先导出 SVG/PDF 等矢量格式，同时提供适合 GitHub 预览的 PNG；
- 不用颜色作为唯一编码，必要时同时使用线型、符号、纹理或直接标注；
- 检查灰度打印、常见色觉差异和窄屏阅读效果。

Matplotlib 官方文档提供了颜色、样式和色觉差异检查的基础入口；后续实现时应以实际版本文档和仓库许可证为准。

## 教学图的最低可读要求

- 一张图只服务一个主要学习目标；
- 图中术语不超过正文能够立即解释的范围；
- 标签尽量靠近对应对象，减少图例和正文之间来回寻找；
- 图下方提供一句“看图提示”，告诉读者应观察什么；
- Markdown 图片提供清楚的 `alt` 文本，SVG 内保留 `<title>` 和 `<desc>`；
- 来源、改绘说明或“作者绘制的示意图”写在图注附近；
- 不使用没有解释价值的装饰性气象照片填充版面。

## 第一课的试片

第一课使用 `assets/weather-climate-map.svg`：它不是观测图，也不表示某个真实事件，而是帮助读者先建立四个概念的边界。后续如果加入南京温度或降水数据，必须另存数据来源、绘图脚本和图注，不能把这张示意图当作证据图。

## 何时创建 `academic-figure` skill

满足以下条件后再创建：

1. 至少完成一张站点时间序列和一张气象地图；
2. 数据读取、单位处理、配色、导出和图注步骤出现重复；
3. 能明确项目默认的 Python 版本、依赖和目录约定；
4. 用一个真实案例验证规则不会妨碍初学者理解。

届时 skill 应覆盖“提出图的问题—核验数据—编写绘图脚本—检查可读性—记录图注与来源—导出”的完整闭环，而不是只规定一套颜色。
