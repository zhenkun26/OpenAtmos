# OpenAtmos 课程 01：气象要素与观测

Status: archived

## 目标

完成课程 01 的第三个知识单元，让学习者把“闷热、起风、下雨”转换为带有时间、地点、单位和资料来源的气象观测记录。

## 范围

- 一篇面向初学者的短课；
- 一张原创“现象—要素—观测平台”SVG 图；
- 一个三日观测记录练习，包含问题、解答和讲解；
- 更新课程入口、资源与任务归档；
- 提交并推送到已确认的 `origin/main`。

## 不在范围内

- 仪器校准、误差传播和观测规范的完整技术培训；
- 相对湿度、露点、风切变等需要热力学或动力学背景的深入推导；
- 把手机传感器或个人目测记录当作正式业务观测；
- 引入新的 Python 依赖、真实数据下载或远程 API；
- force push、重写远程历史或覆盖他人提交。

## 不变量与验收证据

1. 每条观测记录都强调时间、地点、变量、数值/等级、单位和来源。
2. 区分“气象要素”（被描述的量）与“观测平台/仪器”（获取资料的方式）。
3. 说明个人简易记录适合学习变化，不等同于经过规范选址、校准和质控的业务观测。
4. 原创 SVG 包含 `title`、`desc` 和 Markdown 替代文字，不复制外部图片。
5. 课程单元包含现象入口、核心概念、一张图、记录示例、回忆题、常见混淆和下一步入口。
6. 练习目录遵循 `scaffold-exercises` 的 `problem`、`solution`、`explainer` 结构，所有本地目标可解析。
7. 推送前确认远程仓库仍为 `zhenkun26/OpenAtmos`，只推送 `main`，不使用强制覆盖。

## 失败模式与回退

- 内容把“湿度”写成单一含义：明确区分水汽含量、相对湿度和露点，本课只做入门说明；
- 观测表缺少单位或来源：将该字段设为必填，并在示例中明确“校园简易记录”；
- 图表被误读为业务仪器图：在图注标注“教学示意，不表示仪器外形和测量精度”；
- 结构或链接检查失败：修复后再提交，不把未验证材料推送；
- GitHub 推送失败：保留本地提交，记录错误，不重复创建仓库或强推；
- 需要撤销公开变更时使用新的 `git revert <commit>`，不改写已发布历史。
